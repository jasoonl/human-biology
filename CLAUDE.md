# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Unity 6 (6000.6.0f1, Apple Silicon, URP) "Interactive 3D Human Body Explorer" — a classroom teaching tool for AP Biology. Click a structure to read about it at three detail levels, peel away body systems layer by layer, and run a timed identification quiz with spaced-repetition scoring.

Two documents describe the project's intent, and the difference between them matters:

- `Interactive_3D_Human_Body_Explorer.md` — a 100-phase aspirational spec for a commercial-scale medical simulation (HDRP, VR, DOTS/ECS, DICOM, multiplayer, ML segmentation). **It is not a description of what exists.**
- `Planning.md` — the honest translation. It records, per module, what was actually built versus what is a deliberate stub because the dependency (XR headset, Netcode relay, Python ML backend, Dotfuscator licence, CI runner) does not exist here. Read this before assuming a subsystem is real.

Whole directories under `Assets/Scripts/` (`Multiplayer/`, `XR/`, parts of `Dicom/`) are interface-only stubs by design. Don't "fix" them into real implementations without being asked.

## Architecture

### The scene is generated by code, not hand-authored

This is the single most important thing to understand. `Assets/Scenes/Bootstrap.unity` is the only real scene, and almost everything in it — the whole figure, camera rig, lighting, post-processing volume, the full UI, the EventSystem — is produced by `Assets/Editor/HumanBodyExplorerSetup.cs`, invoked from the `Human Body Explorer/` menu or headlessly via `BuildExplorerHeadless`.

**To change what the user sees, edit the build script (or a generator it calls) and re-run it.** Hand-editing the scene in the Editor gets overwritten on the next build. **Never run the build in Play mode** — Unity discards every scene edit when you press Stop (`BuildExplorer` now refuses and saves the scene itself).

The figure is built by `BuildHumanFigure`, which calls the generators in `Assets/Editor/Geometry/` in order: `SkeletonBuilder` (partials: Limbs, Spine, Skull, Extremities), `SkinBuilder`, `MuscleBuilder`, `OrganBuilder` (partials: Thorax, Abdomen, Head, Internals, Airway, Joints), `VesselBuilder`, `NerveBuilder`. There are no literal primitive part definitions any more.

The geometry toolkit (`Assets/Editor/Geometry/`):
- **`Sdf`** — signed distance fields (sphere, ellipsoid, round cone, capsule, chain, torus, plates, half-space, smooth union/subtract/intersect, offset, displace, noise). **`SurfaceNets`** meshes a field (winding verified per face; normals from the gradient). Organs, bones and skin are SDFs — a "suture" is a region mask with a small gap, which is how one skull becomes named bones and one brain becomes lobes.
- **`Loft`** — a Catmull-Rom path with an elliptical cross-section and radius profile: muscles, ribs, vessels, nerves, ligaments. UV.x runs once around, UV.y along the length in metres (the blood-flow shader and the muscle fibre texture depend on this).
- **`TubeKit`** — adds a lofted tube to the scene with its EntityID; `Mirror`, `Beside`, `AlongRib`, and the two placement tricks the vessel/nerve networks use: `UnderSkin` (settle a point a set depth inside the skin field) and `Settle` (onto any field, e.g. the heart).
- **`PartFactory`** creates the scene object (mesh, renderer, MeshCollider, `AnatomyNodeReference`); left/right pairs share one mesh, the right being a negative-X-scale copy (`AddPair`). **`MeshAssets`** saves every mesh under `Assets/Generated/Meshes` with stable GUIDs (≈600 assets, ~100 MB, binary-serialized (EditorSettings serialization mode is Mixed) — expect a big diff after any geometry change; decide before pushing whether to keep them in git or regenerate) and deletes the ones a rebuild no longer produces.
- Landmarks are shared so layers line up: `SkeletonBuilder` joints/`SpineCanal`/`RibPoint`, `BodyShape` limbs (skin and muscles are both defined from these), `SkinBuilder.Field`, `OrganBuilder.HeartField`. Every build ends with `SkinBuilder.ContainmentReport`, naming any structure that pokes through the skin (with the worst vertex position) — keep it at "every structure lies inside the skin".

Things that bit and are now handled: a stray `Combine` of unsaved meshes (`OrganBuilder.Combine` destroys its inputs), tiny meshes need a tight `Sculpt` margin or the sampling grid explodes, `MaterialPropertyBlock` can't be created in a field initialiser, and a `Loft` mesh must be `PartFactory.Save`d before it is placed.

Post-processing: the `AnatomyOutline` full-screen pass (ink contours; it draws on the far side of a depth step and leaves hairline structures uninked) and URP SSAO are added by `AnatomyOutlineFeatureSetup`. Backdrop colour and its contrast check against tissue colours live in `HumanBodyExplorerSetup`.

**Selection UI**: `AnatomyHighlighter` (Scripts/UI) tints and names the part under the cursor (tooltip) and, on click, isolates the selection — it glows while every other part swaps to a translucent ghost (the SkinShell shader) with its collider disabled, so a click goes to the selected part; Esc / empty space clears, H toggles ghosting. It is disabled while a quiz question is open (`QuizController.IsQuestionActive`) because the tooltip would give the answer away. Ghosting and tint touch no material asset (property blocks + a material swap that `Clear` undoes, colliders restored to match the layer toggles).

### EntityID is the spine of the whole system

A single string ID connects five independent subsystems, and nothing else links them:

1. `Assets/StreamingAssets/Data/anatomy_dictionary.json` — ~340 entries, the read-only anatomical knowledge base, loaded by `DataController.LoadDataAsync` into an O(1) dictionary keyed by `entityID`.
2. `AnatomyNodeReference` (`Scripts/Core/`) tags each GameObject with its ID and maintains a **static registry** so lookups don't rescan the scene. Several GameObjects may share one ID (left/right kidney, twelve rib pairs).
3. `AnatomyRaycaster` resolves clicks to IDs and fires two events: `OnNodeSelected` (frontmost) and `OnNodesUnderCursor` (every ID along the ray, nearest first).
4. `QuizController` scores against `OnNodesUnderCursor`, not the frontmost hit — otherwise a structure behind skin or bone would be impossible to answer correctly.
5. `AnatomyLayerVisibility` derives layer membership from the **ID prefix** (`SYS_SK_`, `SYS_MUSC_`, `SYS_NERV_`, `SYS_CV_`, `SYS_INTEG_`, `SYS_REP_`, else Organs), so a new part is classified with no extra wiring. Reproductive ids are `SYS_REP_M_*` / `SYS_REP_F_*`: `AnatomyLayerVisibility.Sex` (the "Reproductive: Male/Female" button) shows only the matching half, since both anatomies share the pelvis. The skin has two meshes sharing `SYS_INTEG_SKIN` — `Skin` (male, with genitals) and `SkinFemale` — and `AnatomyLayerVisibility` shows the one matching `Sex`. The female exterior omits the genitals and adds a light chest; the torso/hips are otherwise shared.

**Camera**: left-drag orbits; right-drag, middle-drag or Shift+left-drag pans; WASD/arrows/Q/E move the focus; scroll zooms; double-click recentres on the spot under the cursor; R/Home resets. Drags that start over UI are ignored. `AdvancedOrbitalCamera` owns the focus point and adopts any direct move of its target (CameraFocusTargeter).

Consequence: adding a structure means adding it in *both* places — a generator call with an `EntityId`, and a matching `entityID` entry in the JSON. Check parity after every build: extract `entityId:` values from `Bootstrap.unity` and compare with the JSON's `entityID`s — they must be identical sets, with no dangling `connectedNodes`. A scene ID with no dictionary entry silently shows nothing; a dictionary entry with no scene object is unquizzable (`QuizController` filters to locatable IDs). Prefix the ID correctly or it lands in the wrong layer toggle.

`AnatomyNode` (`Scripts/Data/`) carries `descriptionPatient`, `descriptionProfessional`, `apBiologyFacts[]` and `clinicalNotes[]` — these map to the three detail levels `ExplorerUIController` cycles through.

### Boot sequence and DI

`GameBootstrapper.Awake` (on the Bootstrap scene root) constructs a hand-rolled `DiContainer`, binds `IDataController` / `IViewController` / `IInputController` / `IDatabaseManager` / `IStudyTracker` / `IAssetStreamingManager`, kicks off the three async initialisations together with `Task.WhenAll`, then calls `GameManager.ConfigureContainer`. `GameManager` is the `DontDestroyOnLoad` singleton every other system reaches through (`GameManager.Instance.DataController`, etc.), so **components must wait for it** — `ExplorerUIController.Start` is a coroutine that yields until `GameManager.Instance` and its subsystems are non-null. Copy that pattern in anything new.

### Two data stores

- **Read-only**: the anatomy JSON in `StreamingAssets`, via Newtonsoft.Json.
- **Mutable**: `userdata.db`, a SQLite file in `Application.persistentDataPath`, reached through `SqliteNative` — raw `DllImport` P/Invoke against the **OS-provided `libsqlite3`**, deliberately avoiding the deprecated `Mono.Data.Sqlite`. This works on macOS Editor and Mac Standalone only; mobile/WebGL would need a bundled native plugin. `StudyTracker` layers spaced repetition over `DatabaseManager`.

### Assembly definitions

Four assemblies: `HumanBodyExplorer.Runtime` (`Assets/Scripts/`), `HumanBodyExplorer.EditorTools` (`Assets/Editor/`), and one asmdef per test folder.

A `CS0246: type or namespace not found` on a Unity type is nearly always a missing asmdef reference, not a missing `using`. Known mappings: `Volume`/`VolumeProfile` → `Unity.RenderPipelines.Core.Runtime`; `InputSystemUIInputModule` → `Unity.InputSystem`; renderer features → `Unity.RenderPipelines.Universal.Runtime`/`.Editor`. Both test asmdefs are `autoReferenced: false` under a `UNITY_INCLUDE_TESTS` define constraint, so they never ship in a player build.

## Project conventions and hard-won gotchas

- **Orientation**: the figure faces **−Z** (anterior is toward the default camera). Therefore **anatomical left is +X**. Getting this backwards put the heart, stomach and spleen on the wrong side once already.
- **Unity primitive sizing**: a sphere's radius is `scale / 2`; a capsule's *total* height is `2 × scale.y`. Both have caused parts to protrude through the skin shell.
- **Real scale**: the figure is 1.75 m with soles at `y = 0`, so positions in the build script are metres of real anatomy.
- **Dedicated `Anatomy` physics layer** — created programmatically by `EnsureLayer()` writing `TagManager.asset`. The orbital camera's collision `SphereCast` **must** exclude it, or the camera collides with the body it is orbiting and ends up inside the figure.
- **`Physics.RaycastNonAlloc` truncates arbitrarily, not by distance** when the buffer fills. With ~1000 colliders the raycaster's `maxHits` is set to 256; lowering it silently drops deep structures from quiz answers.
- **Unity UI needs an `EventSystem`** with an input module, or *no button anywhere fires* with no error. `EnsureEventSystem()` creates one and swaps any legacy `BaseInputModule` for `InputSystemUIInputModule`. This project is on the New Input System; legacy `Input.*` calls won't work.
- **Clicks vs. drags**: `InputManager` fires `OnPrimaryInteract` on *release* only when the pointer moved under ~12 px, because firing on press meant every orbit drag also submitted a quiz answer.
- **Scroll deltas are device-dependent** — a mouse wheel reports ±120, a trackpad ±1. `InputManager` normalises, and `AdvancedOrbitalCamera` scales zoom by current distance so it stays usable when close in.
- **SNOMED CT codes are left blank on new entries.** SNOMED International blocks programmatic lookups and a wrong clinical code is worse than none; the UI hides the line when blank. Codes on entries from the first rounds were typed from memory and are **unverified**.
- **No licensed anatomical meshes exist in this project.** Everything is procedural geometry (SDFs and lofts). Sketchfab / ZygoteBody / Adobe Stock geometry and InnerBody prose are copyrighted and cannot be copied in; anatomical *facts* are not copyrightable. The legal path to real geometry is Z-Anatomy / BodyParts3D (CC-BY-SA), which is a pending open decision.

## Verification expectations

Code in this repo is only "done" once it has actually compiled and its tests have actually run — `Planning.md` sets that standard explicitly and it should be upheld. ## Skin modes
The Skin button cycles Ghost (translucent, default), Solid (opaque skin tone, lit, with depth passes so SSAO
and the outline ignore the bones beneath) and Off. Selecting a part turns a solid skin into a ghost until it is
cleared; clicking the solid skin peels it to Ghost. Logic is in `AnatomyLayerVisibility` (`SkinLook`), the
`_Solid`/`_ZWrite` properties of `SkinShell.shader`, and `AnatomyHighlighter` (hover is blocked behind a solid skin).

## Z-Anatomy anatomy
Bones, muscles, organs, brain, vessels, nerves and the skin now come from the Z-Anatomy atlas (CC BY-SA 4.0, see
`NOTICE.md` and `Tools/ZAnatomy/README.md`). `Geometry/ZAnatomy.cs` swaps each mapped entity's sculpt for the atlas mesh
after the builders run (ids, layers and materials are kept; `zanatomy_map.json` is the id mapping). The skin is a shell
fitted around the atlas structures (`SkinField`), with hair, brows, lips, ears and painted eyeballs (the shell's vertex colour
alpha 0 marks eyes and lashes, which `SkinShell.shader` leaves untinted) and a female variant. Anything the atlas lacks
(female organs, some heart internals) keeps its own sculpt. Source data lives in the git-ignored `ZAnatomyData/`.

Structures the atlas has no centre line or mesh for are laid out in `Tools/ZAnatomy/build_map.py` from landmarks in atlas
space (x left, y up, z back): ileum, phrenic and recurrent laryngeal nerves, cervical/lumbar/sacral plexuses, sacral roots,
splanchnic nerves, thyroid arteries, thoracic duct, and so on. Re-run the script after editing them (it regenerates them
into `ZAnatomyData/zana_lines.json` and rewrites `zanatomy_map.json`). `MeshAssets` records each saved mesh's path itself,
because a mesh created while asset editing is batched has an empty `GetAssetPath` and would otherwise be deleted as stale.
